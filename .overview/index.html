Assignment Submission Portal: End-to-End CI/CD on AWS EKS

A fully automated GitOps-based CI/CD pipeline built for a Flask-based Assignment Submission Portal (Admin & Student roles). Features GitHub Actions OIDC authentication, Amazon ECR, ArgoCD synchronization, Amazon EKS infrastructure, and Prometheus-Grafana monitoring.

CI/CD GitOps Workflow

Push code → GitHub Actions builds → ECR → Manifest repo updated → ArgoCD syncs → Rolling update on EKS

STEP 01

Code Push

Push code to GitHub on the K8s-deployment branch.

STEP 02

Build & Push

GitHub Actions authenticates via OIDC, builds images, and pushes to Amazon ECR tagged with commit SHA.

STEP 03

Manifest Update

CI automatically updates image tags in the separate manifest repository (assignment-portal-k8s).

STEP 04

ArgoCD Sync

ArgoCD detects changes and executes zero-downtime rolling updates on the EKS cluster.

Key Components & Architecture Stack

Application Layer

Flask + Gunicorn (Python 3.12) backend with Admin & Student roles. Nginx frontend serving static assets and proxying API requests.

Data Layer

PostgreSQL 16 for persistent relational storage with GP3 storage class via AWS EBS CSI driver, and Redis 7 for high-performance session caching.

CI/CD & GitOps

GitHub Actions with OIDC (keyless AWS authentication) and Amazon ECR. ArgoCD with auto-sync, prune, and self-heal enabled for declarative continuous delivery.

EKS Infrastructure

Amazon EKS cluster managed with AWS Load Balancer Controller (ALB Ingress), Metrics Server, and HPA autoscaling (2–5 pods) for frontend and backend.

Monitoring & Alerting

Prometheus, Grafana, and Alertmanager (kube-prometheus-stack). ServiceMonitor scrapes /metrics every 30s, configured with 5 critical alert rules (backend down, high CPU/memory, pod restarts, unavailable replicas).
